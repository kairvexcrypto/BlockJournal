# BlockJournal

Журнал изменений блоков для **Paper 1.21.11 / Java 21**. Проект студии **Warndev**.

Плагин записывает установку и разрушение блоков игроками, повреждения от огня и взрывов. Историю можно посмотреть инструментом проверки или командой с фильтрами. SQLite работает в отдельном потоке; очередь событий ограничена по размеру.

## Сборка

Нужны JDK 21 и Maven 3.9+.

```sh
mvn clean verify
```

Готовый файл: `target/BlockJournal-0.1.0.jar`. SQLite включён в сборку. Файл `original-BlockJournal-0.1.0.jar` на сервер не устанавливается.

## Установка

Поместите основной JAR в `plugins`, полностью перезапустите сервер и проверьте `/bj status`. Конфигурация появится в `plugins/BlockJournal/config.yml`. После изменения настроек нужен перезапуск. Folia не поддерживается.

## Команды

| Команда | Назначение | Право |
|---|---|---|
| `/bj help` | Справка | `blockjournal.use` |
| `/bj inspect` | Включить проверку блоков инструментом `BLAZE_ROD` | `blockjournal.inspect`, `blockjournal.lookup` |
| `/bj lookup r:10 t:2h u:Player a:break` | Найти события | `blockjournal.lookup` |
| `/bj next` | Следующая страница текущего поиска | `blockjournal.lookup` |
| `/bj status` | Очередь, ошибки и счётчики записи | `blockjournal.status` |
| `/bj flush` | Запросить сохранение очереди | `blockjournal.admin` |

Для всех команд также требуется `blockjournal.use`. Права по умолчанию доступны операторам. Вместо `u:` можно использовать `uuid:`. Имя сравнивается без учёта регистра с именем **на момент события**.

Центр поиска — блок под прицелом в пределах шести блоков, иначе позиция игрока. `r:` задаёт куб по трём координатам, `r:0` — один блок. Интервал `t:` поддерживает минуты (`30m`), часы (`2h`) и дни (`7d`). Несколько действий разделяются запятой: `a:place,break`.

Время в сообщениях показывается в UTC. Наведите курсор на запись, чтобы посмотреть UUID, координаты и состояния блока. При активной проверке взаимодействие выбранным инструментом с блоком отменяется.

## Хранение

`journal.db` — база SQLite в режиме WAL. Записи добавляются пакетами; у каждой есть уникальный идентификатор события. Повторная доставка резервного пакета не создаёт дублей.

Если SQLite не принимает записи, плагин пытается сохранить пакет в каталоге `spool`. Пакеты имеют версию формата и контрольную сумму. После восстановления базы они перечитываются; повреждённые файлы получают расширение `.corrupt` и остаются на диске для разбора. Резервные пакеты ограничены настройкой `storage.spool-max-mib`.

Срок хранения по умолчанию — 30 дней. Старые записи удаляются небольшими порциями. Файлы базы для резервного копирования проще копировать при полностью остановленном сервере; при работающем сервере нужен согласованный SQLite backup, а не копирование одного `journal.db`.

## Границы версии 0.1.0

- Это журнал событий, без отката мира, инвентарей и содержимого контейнеров.
- Записываются перечисленные Bukkit-события. WorldEdit, прямые изменения блоков другими плагинами, поршни и перемещения жидкостей не охватываются.
- Для разрушения, огня и взрывов поле «После» содержит ожидаемый результат `minecraft:air`, а не повторное чтение мира на следующем тике. Состояние мира могло измениться другим обработчиком.
- Аварийное завершение процесса может потерять ещё не сохранённую очередь. Штатное отключение ожидает сохранение до 15 секунд.
- При заполнении очереди новые события отклоняются, игровой процесс не блокируется. Пропуски отражаются в `/bj status` и журнале сервера. При одновременной недоступности базы и диска сохранность очереди не гарантируется.
- История поиска фиксирует верхнюю границу ID. Новые записи не сдвигают страницы; удаление старых данных по сроку хранения может сократить результат. Резервные пакеты могут появиться в поиске позже.
- Счётчики состояния относятся к текущему запуску. Проверка на живом сервере описана в `ACCEPTANCE.md`.

Исходники Java не содержат поясняющих комментариев. Условия коммерческого использования и передачи прав согласуются отдельно; открытая лицензия этому репозиторию не назначена.
